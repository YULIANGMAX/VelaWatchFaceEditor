# `resource.bin` 二进制格式规范

> ⚠️ **重要声明 / 性质与免责说明**：
> 本文档详述之 `resource.bin` 二进制文件物理区段、文件头偏移量、主题记录结构与描述符格式，**系基于公开工程样本与固件解包数据，通过 AI 辅助逆向工程与反推分析整理得出，并非小米官方发布的正式文件格式规范**。本文档仅供技术研究、底层学习与开源编译器设计参考。

本项目内置编译器（`src/app/core/compiler/`）完整实现此协议标准，无需调用任何第三方外部编译器或私有闭源工具。所有整数若无特别说明，均采用**小端序（Little-Endian）**存储；偏移量均表示从文件起始位置计算的**绝对字节偏移**。

---

## 1. 整体物理布局

二进制文件在磁盘上的物理区段排布如下：

```
┌────────────────────────────────────────────────────────┐
│ 1. 全局文件头 (Global Header, 0xA8 字节)                │
├────────────────────────────────────────────────────────┤
│ 2. 颜色表区 (Color Table, 可选, 4字节对齐)              │
├────────────────────────────────────────────────────────┤
│ 3. 主题记录区 (Theme Records, 每个 0xA0 字节)          │
├────────────────────────────────────────────────────────┤
│ 4. 描述符表区 (Descriptor Tables, 每条 0x10 字节)       │
├────────────────────────────────────────────────────────┤
│ 5. 数据载荷区 (Payloads)                               │
│    ├─ 全部 Layout 坐标数据 (每个 0x10 字节)             │
│    └─ 各可达资源数据 (按 manifest 顺序排列, 含 RLE 图像) │
└────────────────────────────────────────────────────────┘
```

## 2. 全局文件头 (Global Header)

全局头固定长度由设备定义 `binary.header.size` 决定（当前 Vela 设备均为 `0xA8` = 168 字节）：

| 偏移 | 长度 | 类型 | 含义与填充规则 |
| :---: | :---: | :---: | :--- |
| `0x00` | 4 | `u32` | 官方魔数：`5A A5 34 12`（十六进制 `0x1234A55A`） |
| `0x04` | 1 | `u8` | 表盘版本号末段（来自 `description.xml` 的 `version` 末位数字，0~255） |
| `0x10` | 4 | `u32` | 设备/AOD 模式固定标志位（由设备定义 `fixedFields` 写入） |
| `0x18` | 4 | `u32` | 配色方案数（`recolorTable` 或 `colorGroupTable` 的项数，无配色为 0） |
| `0x1C` | 1 | `u8` | 主题总数（`Theme` 数量，含 Normal 与 AOD） |
| `0x1D` | 1 | `u8` | `recolorTable` 项数 |
| `0x1E` | 2 | `u16` | 组合标志（`combinationFlags`）：<br>设备基础值 `|` (存在 Slot / 存在配色 / 普通主题 > 1 ? `0x02` : 0) `|` (存在 AOD ? `0x04` : 0) |
| `0x20` | 4 | `u32` | 首个全局预览图在 BIN 中的绝对文件偏移 |
| `0x28` | 64 | `char[]` | 表盘十进制 ID（UTF-8 编码，以 `\0` 补齐至 64 字节） |
| `0x68` | 64 | `union` | **表盘名称联合体（Watchface Name）**：<br>**情况 A（静态文本）**：直接写入 UTF-8 字符串，剩余字节以 `\0` 补齐至 64 字节（涵盖 `0x68 ~ 0xA7`）。<br>**情况 B（多语言引用 `@name`）**：以 64 字节结构体表示多语言 Translation 字典指针：<br>- `+0x00` (`0x68`): `u32` 标志位 `0xFFFFFFFF`（标记为多语言指针而非普通字符串）；<br>- `+0x04` (`0x6C`): `u24` 资源索引 + `u8` 类型码 `0x06`（Translation）；<br>- `+0x08` (`0x70`): `u32` 保留字节 `0x00000000`；<br>- `+0x0C` (`0x74`): `u32` 表盘名称多语言数据包（Translation Payload）在 BIN 中的物理绝对偏移；<br>- `+0x10` (`0x78`): `u32` 表盘名称多语言数据包的字节长度（如拼图多语言包长度为 39 字节）；<br>- `+0x14 ~ +0x3F` (`0x7C ~ 0xA7`): 28 字节全 `0x00` 补齐。 |

## 3. 颜色表区 (Color Table)

当根元素定义了 `recolorTable` 或 `colorGroupTable` 时，紧接在全局头后写入颜色表：
- 每个颜色占 3 字节，按 **BGR** 顺序排列（如 `#RRGGBB` 存为 `BB GG RR`）；
- 表体末尾向上补齐至 4 字节对齐；
- 若无颜色表，此区段长度为 0。

---

## 4. 主题记录区 (Theme Records)

每个主题在文件中固定占用 `0xA0`（160 字节），包含 `0x58` 字节的 `FaceHeader` 与 `0x48` 字节的主题元信息：

### 4.1 FaceHeader (相对偏移 +0x00 ~ +0x57)
| 相对偏移 | 长度 | 类型 | 含义 |
| :---: | :---: | :---: | :--- |
| `+0x00` | 4 | `u32` | 背景颜色：格式为 `0x80RRGGBB`（小端物理字节为 `BB GG RR 80`） |
| `+0x04` | 4 | `u32` | 该主题专用预览图在 BIN 中的绝对文件偏移（无独立图则为 0） |
| `+0x08` | 80 | `struct[10]` | 10 组元素入口描述表，每组 8 字节 `{count: u32, offset: u32}`，分别指向该主题下对应类型（Type 0~9）描述符列表的条数与绝对起始偏移 |

### 4.2 主题元数据 (相对偏移 +0x58 ~ +0x9F)
| 相对偏移 | 长度 | 类型 | 含义 |
| :---: | :---: | :---: | :--- |
| `+0x58` | 68 | `char[]` | 主题名称（UTF-8 编码，以 `\0` 补齐至 68 字节） |
| `+0x9C` | 4 | `u32` | **AOD 状态标志**：普通主题为 `0x00000000`，息屏（AOD）主题为 `0x00000001` |

## 5. 元素类型码与描述符表 (Descriptors)

元素类型码（Type）定义如下：

| Type | 对应 manifest 资源 | 载荷特征 |
| :---: | :--- | :--- |
| **0** | `Layout` 布局实例 | 固定 16 字节，记录坐标与目标资源映射 |
| **1** | 保留 | 官方固件预留保留字 |
| **2** | `Image` 单图资源 | 包含外层 12 字节头 + RLE 压缩图像块 |
| **3** | `ImageArray` 序列帧 | 包含外层头、帧数、帧长度表及连续 RLE 帧数据 |
| **4** | `Sprite` 动画精灵 | 12 字节固定头，记录引用的 ImageArray 索引、循环次数与帧间隔 |
| **5** | `File` 外部附加数据文件 | 20 字节元信息头 + 文件名 + 二进制原文 |
| **6** | `Translation` 多语言字典 | 8 字节语言位图掩码 + 文本长度表 + UTF-8 字符流 |
| **7** | `DataItem*` 核心数据项 | 统一处理 Text、ImageNumber、ImageValues、Pointer、ProgressBar |
| **8** | `Slot` 槽位与组件容器 | 描述负一屏 / 卡片槽位类型及 appWidget ID |
| **9** | `Widget` 微件组件 | 包含跳转配置、子组件排布坐标及官方 `editBox` 扩展属性 |

每个描述符固定占用 **`0x10`（16 字节）**：
```
+0x00: id (u16, 该类型资源内部局部索引)
+0x02: 保留 (0x00, 0x00)
+0x03: type (u8, 资源类型码 0~9)
+0x04: 保留 (4 字节全零)
+0x08: payloadOffset (u32, 对应载荷在 BIN 中的绝对文件偏移)
+0x0C: payloadLength (u32, 对应载荷的实际字节长度)
```

## 6. 数据载荷 (Payload) 官方物理排序规则

为确保生成的二进制与官方固件完全契合，数据载荷区按以下官方严格顺序输出：

1. **全部 Layout 载荷连续输出**：
   - 依次输出所有 Theme 中包含的 Layout 载荷；
   - 每个 Layout 载荷固定为 16 字节：
     - `+0x00`: 目标资源局部索引（`u24`）；
     - `+0x03`: 目标资源类型码（`u8`）；
     - `+0x04`: 画布 X 坐标（`u16`）；
     - `+0x06`: 画布 Y 坐标（`u16`）；
     - `+0x08..+0x0F`: 8 字节全零补齐。
2. **可达资源载荷输出**：
   - 按照 `manifest.xml` 中资源声明的全局出现顺序，依次输出被任何主题引用的有效资源；
   - 预览图（Preview Image）自然排布在其 Image 声明所在的全局位置；
   - 被 Widget 引用的专用附件（File args）排布在其关联微件之后。

## 7. 图像资源打包标准

图像资源（`type=2` 与 `type=3`）外层头为 `0x0C`（12 字节）：
```
+0x00: 格式码 (u8: RGBA32=0x00, RGB565A8=0x06, indexed8=0x10)
+0x01: 压缩标志 (u8: none=0, RLEReversed=4; recolorEnable 时加 1)
       (若为 ImageArray，+0x01 为帧数，+0x02 为压缩标志)
+0x04: 宽 (u16)
+0x06: 高 (u16)
+0x08: 后续载荷数据字节数 (u32)
```

### 7.1 官方 RLEReversed 编码块 (`E0 21 A5 5A`)
压缩图像均以固件专用解包魔数封装：
```
E0 21 A5 5A
[4 字节 packedFlag: (原始像素长度 << 4) | 像素格式码]
[RLEReversed 压缩字节流...]
```
- **数据包结构**：
  - 高位为 `1`：后续为 Literal 原始像素（低 7 位为长度，最大 127）；
  - 高位为 `0`：后续单个像素重复（低 7 位为重复次数，最大 127）。
- **indexed8 标准量化规范**：
  - 采用标准 WuQuant 算法在 5-bit 色彩空间贪心分割；
  - 采用 **BT.709** 加权色距公式；
  - 采用 **Floyd–Steinberg** 误差扩散抖动；
  - 输出 1024 字节 BGRA 调色板后接逐像素 1 字节索引数组。

## 8. 核心数据项（Type 7 `DataItem*`）体系与二进制布局

### 8.1 架构定位与设计哲学

在 Xiaomi Vela 表盘固件架构中，**Type 7 是唯一负责将实时数据（时间、日期、步数、心率、电量、天气等）渲染至屏幕的核心数据消费层**。

- **为什么叫 Type 7？**
  固件内部不识别复杂的 XML 标签名，而是将所有具备「数据源驱动」特性的组件，统一分配资源类型码 `0x07`。无论是数字、文本、指针还是进度条，在底层解析器眼中皆为 Type 7 实例。
- **Type 7 家族包含哪些 XML 组件？**
  1. `<DataItemText>`：调用内置矢量/点阵字模排版的动态文本（支持单行、折行与弧形）；
  2. `<DataItemImageNumber>`：以切片序列帧渲染的多位数字（如时间大字、计步数值）；
  3. `<DataItemImageValues>`：按离散状态映射图标的切图（如天气图标、蓝牙开关状态）；
  4. `<DataItemPointer>`：围绕指定锚点随数值旋转的模拟指针（时针、分针、秒针）；
  5. `<DataItemProgressBar>`（`<DataItemArcProgressBar>` / `<DataItemLineProgressBar>`）：线形或圆弧轨迹进度条。

- **通用头部协议（前 8 字节）**：
  所有 Type 7 载荷均共享统一的前 8 字节结构：
  - `+0x00 ~ +0x05`（6 字节）：主数据源绑定（DataSource Code，如 `timeMinute`、`stepCurrent` 等）；
  - `+0x06 ~ +0x07`（2 字节，`u16` Little-Endian）：刷新周期与动画插值参数（`parameter`，默认 1000ms）。

---

### 8.2 `DataItemText` 文本载荷二进制完整位域

`DataItemText` 载荷固定头部为 48 字节（`0x30`），其后紧跟 UTF-8 格式字符串与子级数据源编码数组：

```
+0x00 ~ +0x05: 基础数据源绑定 (6 字节 DataSource Code)
+0x06 ~ +0x07: 动画参数 / 刷新周期 (u16, parameter, 默认 1000)
+0x08 ~ +0x0A: 文本颜色 (3 字节, BGR 顺序, 如 #FF4444 存为 44 44 FF)
+0x0B:         不透明度 (u8, 0~64 硬件标定值，由 opacity 0~100 线性映射)
+0x0C:         字号 (u8, fontSize, 单位像素)
+0x0D ~ +0x0E: 字体/字重/字间距复合位域 (u16, Little-Endian):
               - bits 0..5:   fontId (misanslatin=0, misansw=1, misanstc=2, misans=3, notosans=5)
               - bits 6..9:   fontWeight (bold=0, regular=7 等)
               - bits 10..15: letterSpace (字间距，0~63 像素，官方标准编码)
+0x10:         排版/对齐/溢出模式复合位域 (u8):
               - bits 0..2: align (left=0, center=1, right=2)
               - bits 3..5: longMode (wrap=0, dots=1, scroll=2, scroll_circular=3, clip=4)
               - bit 6:     isArc (普通矩形=0, 弧形排版=1)
+0x14 ~ +0x1B: 布局形态专属区段 (8 字节):
               [普通矩形 style="normal"]
               - +0x14: 复合位域 (u32, Little-Endian):
                 * bits 0..7:   lineSpace (行间距，0~255 像素)
                 * bits 8..17:  w (文本区域宽度，10 位无符号数，最大 1023 像素)
                 * bits 18..27: h (文本区域高度，10 位无符号数，最大 1023 像素)
               - +0x18: rotation (i16, 旋转角 * 10)
               - +0x1A: 保留补齐 (2 字节全零)
               [弧形排版 style="arc"]
               - +0x14: radius (u8, 基准半径像素)
               - +0x15: verticalAlign (u8 径向对齐: top=0 外圈, center=4 中圈, bottom=8 内圈)
               - +0x18: startAngle (i16, 起始极角 * 10)
               - +0x1A: span (i16, 覆盖跨度角 * 10)
+0x2C ~ +0x2F: 格式串与子数据源计数 (u32, Little-Endian):
               - bits 0..7:  formatLength (格式字符串 UTF-8 字符字节数)
               - bits 8..15: sourcesCount (子级 <Content> 数据源引用个数)
+0x30 ~ ...:   变长数据体:
               - format 字符串原文 (UTF-8 字符流，长度为 formatLength)
               - 各子级数据源编码 (每个 2 字节，紧随字符串后依次排列)
```

## 9. 编译一致性保证

本编译器遵循以下不可变原则：
1. **纯正官方布局**：全盘采用官方绝对偏移、FaceHeader 结构与载荷排序，不夹杂任何过时第三方工具的私有结构；
2. **静态校验拦截**：当 XML 中存在未知节点、超出硬件支持的属性值或损坏引用时，在编译前坚决予以明确阻断，杜绝产生损坏固件的非法字节；
3. **确定性输出**：相同项目源码与素材输入，构建出的二进制散列值（SHA-256）恒定一致。
