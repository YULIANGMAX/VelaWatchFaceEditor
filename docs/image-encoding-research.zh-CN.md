# 图像编码与量化研究

> ⚠️ **重要声明 / 性质与免责说明**：
> 本文档汇总之图像资源编码格式、像素通道排布、调色板算法及 WuQuant 量化管线，**系利用 AI 辅助逆向测试、数据特征比对与穷举反推所得出的技术分析结论，并非小米官方发布的技术说明**。

本文档汇总针对小米 / HyperOS Vela 表盘二进制图像资源（`resource.bin` 中 `type=2` Image 与 `type=3` ImageArray）编码机制、量化算法与第三方实现的深度逆向分析结论，为编译器图像管线演进提供技术参考。

---

## 1. 固件支持的像素格式与封装

Vela 固件解包器原生支持三种像素解压格式，均通过标准 RLEReversed（魔数 `E0 21 A5 5A`）进行行内数据包化：

| 格式码 | 标识名 | 像素排列 | 数据存储特点 | 固件支持 | 体积与品质权衡 |
| :---: | :--- | :--- | :--- | :---: | :--- |
| `0x00` | **RGBA32** | 原始 BGRA 4 字节/像素 | 8-bit 每通道无损 | 原生支持 | 文件体积最大（~4x），零量化损耗，完全无需调色板 |
| `0x06` | **RGB565A8** | RGB565 (2B) + Alpha (1B) | 3 字节/像素紧凑无损 | 原生支持 | 体积居中，适合大面积半透明或渐变图形 |
| `0x10` | **indexed8** | 1024B BGRA 调色板 + 1B 索引 | 1 字节/像素 + 调色板 | 原生支持 | 文件体积最小，色彩上限 256 色，需量化 |

## 2. 官方 WuQuant 量化器算法特征反推

通过对官方样本 `resource.bin` 中提取的调色板及索引数组进行逆向比对与穷举测试，推导出官方量化管线的完整特征：

### 2.1 算法管线
1. **输入归一化**：标准 RGBA 8-bit（非隔行 PNG），全透明像素预处理（清除不可见 RGB 噪点）；
2. **三维直方图构建**：基于 `significantBits = 5`（$32 \times 32 \times 32$ 色彩立方体）统计矩与方差；
3. **Wu 贪心切割**：按最大方差优先选择 box 进行轴向二分切割；
4. **色彩距离公式**：穷举比对证实官方采用 **`euclidean-bt709`** 加权欧氏距离：
   $$D = 0.2126 \cdot \Delta R^2 + 0.7152 \cdot \Delta G^2 + 0.0722 \cdot \Delta B^2$$
5. **矩质心一次精炼**：以截断质心均值确定最终调色板代表色（非 Lloyd 迭代）；
6. **误差扩散**：使用 Floyd–Steinberg 抖动算法将量化误差扩散至相邻像素；
7. **RLE 包装**：使用高位为 1 标识 literal、为 0 标识 repeat 的 7-bit 游程编码（最大包长 127）。

### 2.2 JS 实现与官方 C/C++ 实现的微小残差成因
在 `image-q`（TypeScript/JavaScript）与小米官方量化器（C/C++ 原生移植）的比对中，大部分图像可实现 100% 字节级一致，少部分带平滑 Alpha 渐变的图像存在 $\le 1$ 字节调色板偏差或个别边缘 box 分裂 tie-break 差异：
- **微数值截断分歧**：浮点精度的微小差异使个别边界像素在划分归属时落入相邻 box，使得该 box 代表色的整数均值产生 $\pm 1$ 的微差（如绿色分量 209 vs 210）；
- **肉眼不可感知**：此类 $\le 1$ 通道差在穿戴设备高 PPI 屏幕上完全不可见，且不影响文件结构与固件解码安全性。

## 3. 第三方编译器 (WatchfaceCompiler.exe) 策略分析

分析社区流传的第三方逆向编译器 `WatchfaceCompiler.exe`（基于 C++ / stb_image / zlib 构建），其处理策略具有重要参考价值：

1. **完全绕过量化难题**：
   - 该编译器内部**未集成任何调色板量化算法**（如 WuQuant、NeuQuant 或 MedianCut）；
   - 对所有图像资源默认强制按 `RGBA32` 或 `RGB565A8` 格式输出；
   - 像素直接转为 BGRA 后封装 `E0 21 A5 5A` 官方 RLE。
2. **以空间换兼容性**：
   - 牺牲了 indexed8 的极致体积压缩优势，换取了 100% 图像保真度与 0 量化错误；
   - 由于固件底层原生识别 RGBA32 RLE，其产出的 BIN 能在手表上完美加载运行。

## 4. 本项目编译器的三级图像处理策略

结合上述研究，本编辑器内置编译器（`src/app/core/compiler/image.ts`）实现了最完备的三级图像编码架构：

```
                    ┌─────────────────────────┐
                    │      PNG 输入图像        │
                    └────────────┬────────────┘
                                 │
             ┌───────────────────┼───────────────────┐
             ▼                   ▼                   ▼
    【精确索引模式】       【无损真彩模式】      【高质量量化模式】
    (encodeExactIndexed8) (encodeBgra32/RGB565) (encodeQuantizedIndexed8)
             │                   │                   │
      源图 ≤ 256 色       用户指定无损格式     源图 > 256 色 且需小体积
             │                   │                   │
      直接提取颜色集合     按 BGRA / 565A8 编码   WuQuant + BT.709 距离
      零量化损耗           视觉 100% 无损       Floyd-Steinberg 误差扩散
      与官方逐字节一致     绕过量化算法差异     体积最小化
             │                   │                   │
             └───────────────────┼───────────────────┘
                                 ▼
                     ┌───────────────────────┐
                     │   RLEReversed 打包    │
                     │  (魔数 E0 21 A5 5A)   │
                     └───────────────────────┘
```

1. **精确建表（首选）**：对于颜色数 $\le 256$ 的切图，直接提取精确色表生成 indexed8，不经过任何量化与抖动，输出结果最精确、体积最小；
2. **无损兼容（可选）**：支持将格式指定为 `RGBA32` 或 `RGB565A8`，直接输出无损 RLE 像素，杜绝任何颜色偏差；
3. **自适应量化（备选）**：超 256 色切图采用标准 WuQuant 与 BT.709 距离完成调色板提取与抖动，保证在体积受限场景下的最佳视觉呈现。
